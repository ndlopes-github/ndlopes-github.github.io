## BoostRace animation

`make.sh` takes notebook code cells 0–51 verbatim as the model and runs one race with the notebook's seed. It stores positions every 15 s (`sim.jl`) and renders 1000×500 frames with Plots/GR (`render.jl`). It needs `julia`, `jq`, `ffmpeg` and ImageMagick.

- **Patch needed on Julia ≥ 1.12:** notebook cell 23 re-assigns the `const coursename` to the same value. That is an error since Julia 1.12, so the line is commented out. Nothing else in the model is touched.
- **Display-only lateral position:** the model is one-dimensional (distance along the course). In the plot, each runner gets a fixed U(0,1) fraction of the local road width (seed 7), so dots move smoothly instead of flickering.
- **Reproducibility:** the run uses Julia 1.13.1 and the pinned `Manifest.toml`. Julia's RNG streams and Distributions' samplers can change between versions, so this run is not guaranteed to match the paper's Julia 1.8 runs number for number. It is the same model with the same parameters.

## Gallery

The gallery clips in `media/gallery/` are built from `tools/gallery/clips.tsv` by `tools/gallery/build.sh` (see the script header for the column format). Sources are Arquivo.pt captures of the 2011 site (`arq:`, `https://arquivo.pt/wayback/2011id_/http://ptmat.fc.ul.pt/~ndl/<path>`), the local backup of the same site (`bak:`, same `<path>` under `$GALLERY_BACKUP`, default `/media/nuno/Warehouse/TOSHIBA/BackUP/mywebpages/public_html`), YouTube videos, and local files. Arquivo.pt truncated captures at 10 MB, so `ringtest`, `wu-fkdv` and `toytsunami-basin` are now built from the full-length originals in the backup; `maxframes` remains for truncated captures. Clips longer than 30 s are sped up to 30 s and clips shorter than 8 s are slowed down to 8 s (either way by at most 4×); then they are scaled to ≤ 480 px wide and encoded at CRF 30. Only `tagus-currents` (58 frames, 12-minute snapshots) is slowed down. An optional ninth column sets where the poster frame is taken (default 0.6 of the clip). `race-hist` and `race-speed` use 0.2, while the field is still on the course.

The three molding clips (`mould-*`) are the ParaView GIFs of the MathMould OpenFOAM cases, run with the custom `mathMould` solver (three phases: air, melt, water). They come from `/media/nuno/Warehouse/nuno_folder_backup_23_02_2024/OpenFoam_v2006/mathMould_Case{1,2}/img/`, the same files as in the `img/` folders of the private repositories `ndlopes-github/mathMould_Case1` and `_Case2` (not linked). The field shown is `alphas` = Σ i·αᵢ in the order of each case's phase list. In Case 1, `(water melt air)` gives blue water, grey melt and red air. In Case 2, `(air water melt)` gives cyan air, blue water and yellow melt. Captions follow the repositories' READMEs:
- Case 1 is "2D case with one inlet (water) and one outlet". `noSlipmovie` uses no-slip walls without the pressure correction in the viscosity model.
- Case 2 is "2D case with two inlets (melt and water) and one outlet". `movie` uses slip walls with T_r = 273.15 K. `noSlipTrModmovie` uses no-slip walls with the pressure correction and T_r = 153.15 K.

Colour bars and axis triads are cropped away. The Case 1 tube (about 1:10) is turned clockwise (`transpose=1`) to fit the 4:3 tiles, so injection comes from the left; the caption says so.

The three race clips (`race-*`) are rendered from the public BoostRace notebook (`origin/main:JLRace.ipynb`), from the same run as `race-boostrace.mp4`: `VIEWS=1 tools/boostrace/make.sh <notebook>` writes them to the gallery cache, then `build.sh` encodes them. `sim.jl` also keeps the runners' speeds and the congestion weight ρ (the notebook's `R`: speed = (1 − ρ)·free speed + ρ·speed of the slower runners ahead), and `views.jl` draws them; the model cells are untouched. Display choices: 50 m bins (the notebook's own histogram uses 4 m, below a pixel at tile size), fixed vertical scales over the whole race, viridis for ρ ∈ [0, 0.8]. Nothing comes from BoostRace2 (user decision).

Two 2016 YouTube clips were dropped as duplicates of older runs (checked frame by frame): `BotK383Xk7A` is `tau1dt001Hnl` (now `landslide-cdg`, Xd3d dated 14/12/09), and `86FZPF3LhxE` is the 2011 DOLFWAVE `tsunami.gif` (now `tsunami-2011`). Their "2016" was the upload year, not the computation year.

Three clips were added in Oct 2026:
- `horseshoe-lisbon` and `horseshoe-tagus-mouth` come from GVWave commit `9761875` (`scripts/horseshoe1969_animate.jl lisbon` and `mouth`). The crop keeps only the inside of the map frame(s); the title, colour bars and gauge records are dropped. The mouth crop keeps both maps (open, closed) and the white gap between them.
- `tsunami-3d` (YouTube `mesCz0e27qs`) was the Water waves card's clip until the 1969 Horseshoe animation replaced it. It uses the card's old crop, which keeps the colour bar and the time label. It shows the same coastline and ring source as `tsunami-2011`, but as a different render (the bathymetry as a wireframe), like `tsunami-velocities`. Whether it is the same run was not checked. `~/scripts/yt-dlp` 2026.06.09 downloaded it without a 403.

Captions follow the pages that first showed each film: the 2007 Navier–Stokes pages (`NStokes/`), the Boussinesq report (`Bouss/`), the DOLFWAVE gallery and demo pages (`other/dolfin.dir/`, `doc/`), and the MSc thesis (`tese_mest/tese.pdf`, §7.2–7.3). Captions carry no years: the gallery intro gives the periods (Navier–Stokes and Tagus 2003–2007, Boussinesq-type waves up to 2012, DOLFWAVE in Julia 2026). The model is written Zhao–Teng–Cheng, the author order of Zhao, Teng and Cheng (2004), *Ocean Engineering*, doi:10.1016/j.oceaneng.2004.03.010 (checked on Crossref); the 2009–2011 pages wrote Zhao–Cheng–Teng. The landslide pair (`underzhao`, `tau1dt001Hnl`) is identified with the DOLFWAVE `hLandslide/LPTcdgHnl` demo: the two films sit side by side in the 2009 gallery and show the same moving-bottom dipole as the demo.

## Publications

`tools/pubs/pubs.toml` is the single source for the Publications list and the papers under review. Running `julia tools/pubs/build.jl` (standard library only) regenerates the HTML and BibTeX. Metadata was checked against Crossref (journal records) and the published PDFs. Abstracts come from Crossref where the publisher deposited one; otherwise from the published PDF (COSE 2026) or the authors' final LaTeX (CAMWA 2021). Each entry's comment names its source.
